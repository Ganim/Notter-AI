# Alpha 4.0a — Supabase Auth (Login/Signup)

## Overview

Add optional authentication to AgentTrack using Supabase Auth. Users can login with email/password or OAuth (Google, GitHub). The app remains fully functional without login — auth is 100% optional and only required for future sync features (4.0b).

## Auth Flow

1. User clicks "Login" in User Menu → Auth Dialog opens
2. Dialog has two tabs: "Login" and "Sign Up"
3. **Login tab**: email + password fields, "Login" button, OAuth buttons (Google, GitHub)
4. **Sign Up tab**: email + password + confirm password fields, "Create Account" button
5. **OAuth**: `supabase.auth.signInWithOAuth()` opens external browser, callback redirects back to app
6. After successful auth, dialog closes, User Menu shows user email + "Logout" button
7. Session persisted automatically by Supabase SDK (refresh tokens in localStorage)

## Supabase Client

Create a singleton Supabase client at `src/lib/supabase.ts`:

```typescript
import { createClient } from '@supabase/supabase-js';

const SUPABASE_URL = import.meta.env.VITE_SUPABASE_URL || '';
const SUPABASE_ANON_KEY = import.meta.env.VITE_SUPABASE_ANON_KEY || '';

export const supabase = createClient(SUPABASE_URL, SUPABASE_ANON_KEY);
```

Environment variables stored in `.env` (gitignored):
```
VITE_SUPABASE_URL=https://xxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```

A `.env.example` is committed with empty values as documentation.

## Auth Store

Zustand store at `src/stores/auth-store.ts`:

```typescript
interface AuthState {
  user: User | null;
  session: Session | null;
  loading: boolean;

  initialize: () => Promise<void>;    // check existing session on app start
  signInWithEmail: (email: string, password: string) => Promise<{ error?: string }>;
  signUpWithEmail: (email: string, password: string) => Promise<{ error?: string }>;
  signInWithOAuth: (provider: 'google' | 'github') => Promise<{ error?: string }>;
  signOut: () => Promise<void>;
}
```

- `initialize()` is called on app mount to restore existing session
- Listens to `supabase.auth.onAuthStateChange()` to keep state in sync

## Auth Dialog

`src/components/AuthDialog.tsx`:

- Triggered from UserMenu "Login" button
- Two tabs: Login | Sign Up
- Login: email input, password input, "Login" button, separator, Google + GitHub OAuth buttons
- Sign Up: email input, password input, confirm password input, "Create Account" button
- Error messages displayed inline below the form
- Loading states on buttons during auth operations
- On success: dialog auto-closes

## OAuth in Tauri

OAuth flows open the system browser. For the callback:
- Supabase redirects to a URL after OAuth completes
- In Tauri desktop, we use `tauri-plugin-deep-link` to register a custom URL scheme (`agenttrack://auth/callback`)
- Alternatively, redirect to `http://localhost:1420` during dev and let the app catch the session from URL params
- The Supabase SDK handles token extraction from the callback URL automatically via `supabase.auth.getSessionFromUrl()`

For MVP, we use the simpler approach: redirect to localhost during dev. Deep links can be added later for production builds.

## Prerequisites

A Supabase project must be created at supabase.com with:
- Email auth enabled
- Google OAuth provider configured (optional)
- GitHub OAuth provider configured (optional)

## Out of Scope (Alpha 4.0c)

- User profile / avatar
- Auth-based permissions
