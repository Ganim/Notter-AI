# Alpha 3.0a — Agent Configuration & Test Chat

## Overview

Enhance the AgentsTab with a test chat panel and full multi-provider support. The AgentsTab is for **configuring and testing** agent profiles — not for production work (that comes in the Workflow tab, Alpha 3.0b).

## Layout

```
┌──────────────────────────────────────────────────────────────────┐
│  Sidebar (30%)     │  Config (35%)          │  Test Chat (35%)   │
│                    │                        │                    │
│  [+ New Agent]     │  Nome: ___________     │  ┌──────────────┐ │
│                    │  Provider: [Ollama ▾]  │  │ Agent: Olá!   │ │
│  ● Assistente ◄── │  Model: [llama3.2 ▾]  │  │               │ │
│  ○ Backend Dev     │  API Key: ********     │  │ You: Como...  │ │
│  ○ Reviewer        │  System Prompt:        │  │               │ │
│                    │  ┌────────────────┐    │  │ Agent: ...    │ │
│                    │  │                │    │  └──────────────┘ │
│                    │  └────────────────┘    │  ┌──────────────┐ │
│                    │  [x] Autonomous        │  │ Type message  │ │
│                    │                        │  └──────[Send]──┘ │
└──────────────────────────────────────────────────────────────────┘
```

- Screens < 900px: chat stacks below config (vertical layout)
- Switching agents in sidebar switches the chat
- Chat history is ephemeral (not persisted between sessions)

## Chat Panel Behavior

- Label: "Test Chat" / "Chat de Teste"
- Placeholder: "Envie uma mensagem para testar a configuração deste agente"
- "Clear" button to reset conversation
- Status indicator: connected / error / loading
- On provider failure, show clear error (e.g., "Ollama não está rodando", "API key inválida")
- System prompt from agent profile is injected automatically
- Messages are simple user/assistant turns (no tool calling in test chat)

## Model Selection

Add `model` field to `AgentProfile`. Models vary by provider:

| Provider | Source | Default |
|----------|--------|---------|
| Ollama | Dynamic via `GET /api/tags` (lists installed models) | First available |
| OpenAI | Hardcoded list: `gpt-4o`, `gpt-4o-mini` | `gpt-4o-mini` |
| Anthropic | Hardcoded list: `claude-sonnet-4-20250514`, `claude-haiku-4-5-20251001` | `claude-sonnet-4-20250514` |
| Gemini | Hardcoded list: `gemini-2.0-flash`, `gemini-2.5-pro` | `gemini-2.0-flash` |

- Model select updates dynamically when provider changes
- Ollama model fetch goes through Rust proxy (reuse `llm_request`)
- If Ollama fetch fails, show error + allow manual input

## Unified Chat Module

Create `src/lib/chat.ts` — single multi-provider chat interface:

```typescript
interface ChatMessage {
  role: 'system' | 'user' | 'assistant';
  content: string;
}

interface ChatResponse {
  content: string;
  error?: string;
}

function sendChat(profile: AgentProfile, messages: ChatMessage[]): Promise<ChatResponse>
```

- Uses Rust proxy (`llm_request`) for all providers (avoids CORS)
- Each provider has its own request builder + response parser
- `translator.ts` refactored to use `chat.ts` internally
- `llm.ts` removed (replaced by `chat.ts`)

### Provider request/response mapping

**Ollama:** POST `/api/chat` → `data.message.content`
**OpenAI:** POST `/v1/chat/completions` → `data.choices[0].message.content`
**Anthropic:** POST `/v1/messages` → `data.content[0].text`
**Gemini:** POST `/v1beta/models/{model}:generateContent` → `data.candidates[0].content.parts[0].text`
