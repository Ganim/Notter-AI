# Alpha 2.0 — Real Terminal with PTY

## Overview

Replace the current command-response terminal (CMD invoke per command) with a real pseudo-terminal (PTY) powered by `portable-pty` in Rust. The terminal becomes fully interactive — supporting shell state, programs like vim/htop/claude, and streaming I/O.

---

## Architecture

```
Frontend (xterm.js) ←→ Tauri Events/Commands ←→ Rust (portable-pty) ←→ Shell
```

### Layers

1. **xterm.js (Frontend)** — Renders terminal UI, captures keystrokes, displays output. No HTML input field — typing goes directly into xterm.
2. **Tauri IPC** — Commands for lifecycle (create, write, resize, close). Events for streaming output and exit signals.
3. **PtyManager (Rust)** — Manages a HashMap of active PTY sessions. Each session has a reader thread that streams output to the frontend.
4. **Shell** — Auto-detected: WSL bash if available, PowerShell otherwise.

## Rust Backend

### Dependencies

Add to `src-tauri/Cargo.toml`:

```toml

```

### PtyManager

A `Mutex<HashMap<String, PtySession>>` stored in Tauri managed state.

At creation time, `portable-pty`'s `PtyPair` is decomposed into separate handles because `PtyPair` itself is not `Send`. The master is used to obtain a reader (cloned) and writer, and is retained for resize operations.

```rust
struct PtySession {
    writer: Box<dyn Write + Send>,
    master: Box<dyn MasterPty + Send>,  // retained for resize
    child: Box<dyn Child + Send>,
    cancel: Arc<AtomicBool>,            // signals reader thread to stop
}

struct PtyManager {
    sessions: Mutex<HashMap<String, PtySession>>,
}
```

**Ownership split at creation:**
1. `pair.master.try_clone_reader()` → moved into reader thread
2. `pair.master.take_writer()` → stored as `writer` in session
3. `pair.master` → stored as `master` for `resize()` calls
4. `pair.slave` → consumed by `CommandBuilder::new_command` to spawn child, then dropped

### Tauri Commands

| Command | Params | Behavior |
|---------|--------|----------|
| `create_pty` | `id: String, cols: u16, rows: u16` | Detect shell, spawn PTY with given size, start reader thread, store session. Returns `Result<(), String>` with error if PTY creation, shell detection, or spawn fails. |
| `write_pty` | `id: String, data: String` | Write bytes to PTY writer |
| `resize_pty` | `id: String, cols: u16, rows: u16` | Call `master.resize()` on the stored master handle |
| `close_pty` | `id: String` | Set `cancel` flag to true, kill child process, remove session from HashMap |

### Tauri Events (Rust → Frontend)

Uses single event names with ID in payload (simpler listener management):

| Event | Payload | When |
|-------|---------|------|
| `pty-output` | `{ id: String, data: String }` | PTY reader receives data |
| `pty-exit` | `{ id: String, code: i32 }` | Shell process exits |

The frontend listens to `pty-output` once and filters by `id`.

### Reader Thread

For each PTY session, spawn a thread that:
1. Receives a cloned reader from `pair.master.try_clone_reader()` and an `Arc<AtomicBool>` cancel flag
2. Reads in chunks (4KB buffer) in a loop
3. On each iteration, checks `cancel.load(Ordering::Relaxed)` — if true, breaks
4. Converts bytes to String via `String::from_utf8_lossy` (known limitation: may corrupt non-UTF8 binary output, acceptable for Alpha 2.0)
5. Emits `pty-output` event via `app_handle.emit()` with `{ id, data }`
6. On EOF or read error, emits `pty-exit` with exit code and breaks

**Cleanup:** When `close_pty` is called, it sets the cancel flag. The reader thread will exit on the next loop iteration or when the read returns an error (child killed). The thread is not joined — it is a detached daemon thread that self-terminates.

### Shell Detection

```rust
fn detect_shell() -> (String, Vec<String>) {
    // Default: PowerShell (always available on modern Windows)
    // PowerShell is the expected default for a Windows desktop app
    let ps = ("powershell".into(), vec!["-NoLogo".into()]);

    // Check if WSL has a valid distro (not just installed)
    match Command::new("wsl").arg("-e").arg("echo").arg("ok").output() {
        Ok(output) if output.status.success() => {
            ("wsl".into(), vec!["bash".into()])
        }
        _ => ps,
    }
}
```

Priority: PowerShell as default. If WSL has a working distro, use bash. This avoids surprising users who have WSL installed but don't use it. Shell selection UI planned for future.

### Error Handling

| Scenario | Behavior |
|----------|----------|
| PTY creation fails (old Windows, ConPTY unavailable) | `create_pty` returns `Err` with descriptive message. Frontend shows error in terminal area. |
| Shell binary not found | `create_pty` returns `Err`. Frontend shows error. |
| WSL detection passes but bash fails to launch | `detect_shell` validates with `wsl -e echo ok`. If that fails, falls back to PowerShell. |
| `write_pty` to non-existent session | Returns `Err("session not found")`. Frontend ignores silently. |
| Reader thread crashes | `pty-exit` event is emitted. Frontend shows red status dot. |

### Security Note

`portable-pty` spawns processes directly via OS APIs (ConPTY on Windows), bypassing Tauri's shell plugin sandbox. This is intentional — a PTY requires direct process control. The trust level system (Alpha 3.0) will gate which commands agents can inject. For Alpha 2.0, the user has full control of the terminal.

## Frontend

### TerminalView.tsx — Full Rewrite

**Removed:**
- HTML `<input>` field and Play button
- `invoke("execute_command")` calls
- Manual command-response pattern

**Added:**
- `create_pty` called on mount with xterm cols/rows. If it fails, display error message in terminal area.
- `xterm.onData(data)` → `invoke("write_pty", { id, data })`
- `listen("pty-output")` → filter by `id`, then `term.write(data)`
- `listen("pty-exit")` → filter by `id`, update status indicator
- `xterm.onResize({ cols, rows })` → `invoke("resize_pty", { id, cols, rows })`
- Cleanup on unmount: `invoke("close_pty", { id })`, unlisten events

**xterm.js configuration:**
- `cursorBlink: true`
- `scrollback: 5000`
- Theme matches app dark/light mode

### TerminalHandle Interface

```typescript
export interface TerminalHandle {
  writeln: (text: string) => void;
  writeInput: (data: string) => Promise<void>;  // programmatic input for Alpha 3.0
}
```

`writeInput` calls `write_pty` to inject commands — preparation for agent executor.

### Status Indicator

- Green dot: shell running
- Red dot: shell exited
- Clicking a dead terminal offers to restart
